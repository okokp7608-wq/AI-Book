# 김포페이 가맹점 지도 웹앱 — 개발 플랜

김포시청 "가맹점 조회" 게시판(bbsNo=573)의 가맹점 정보를 수집해
지도에 표시하고, **상호명 / 주소**로 검색할 수 있는 웹앱을 만든다.

- 데이터 출처: https://www.gimpo.go.kr/portal/selectBbsNttList.do?bbsNo=573&key=1283
- 목표: 정적 웹앱 + 주기적 자동 갱신 파이프라인 (서버 운영비 0원)

---

## 1. 전체 구조

```
[수집]  scraper/  ──> data/raw/merchants.raw.json      (게시판 스크랩 결과)
          │
[정제]  scraper/normalize  ──> 주소 정규화 / 중복 제거
          │
[좌표]  scraper/geocode    ──> data/cache/geocode.json (주소→좌표 캐시, 재사용)
          │
[산출]  web/public/data/merchants.json  (+ 검색 인덱스, gzip)
          │
[표시]  web/  React + 지도 SDK  ──> GitHub Pages 정적 배포
          │
[자동]  .github/workflows/refresh.yml (주 1회 cron) ──> 변경분만 커밋
```

핵심 설계 원칙
- **런타임 서버 없음.** 스크랩·지오코딩은 빌드/CI 시점에만 수행하고,
  브라우저는 완성된 JSON 하나만 받는다.
- **지오코딩은 캐시가 자산.** 주소→좌표 결과를 저장소에 커밋해 두고
  신규 가맹점만 추가 호출한다 (API 쿼터·시간 절약).
- **검색은 클라이언트에서.** 데이터가 수천~1만 건 규모이므로
  브라우저 메모리에서 충분히 즉시 검색된다.

## 2. 데이터 수집 (scraper)

### 2.1 대상 URL 패턴
```
목록  /portal/selectBbsNttList.do?bbsNo=573&key=1283&pageIndex={N}&pageUnit={10|50|100}
검색  ...&searchCnd=all&searchKrwd={키워드}
상세  /portal/selectBbsNttView.do?bbsNo=573&key=1283&nttNo={ID}  (실제 파라미터명 확인 필요)
```
- 검색 결과상 `pageIndex`가 900번대까지 존재 → **총 수천~1만 건 규모**로 추정.
- `pageUnit`을 100으로 키워 요청 수를 1/10로 줄일 수 있는지 먼저 검증.

### 2.2 구현
- Node.js + `undici`(fetch) + `cheerio`(HTML 파싱)
- 인코딩 확인 (EUC-KR이면 `iconv-lite`로 변환)
- 요청 간 300~500ms 지연, 동시성 2 이하 → 상대 서버 부담 최소화
- `robots.txt` / 이용약관 확인 후 준수
- 실패 페이지는 재시도 큐에 넣고 지수 백오프 (2s/4s/8s)

### 2.3 증분 수집
- 첫 실행: 전체 페이지 순회 (풀 스캔)
- 이후: 최신 페이지부터 읽다가 **이미 저장된 게시글 ID를 만나면 중단**
- 월 1회는 풀 스캔으로 삭제된 가맹점(폐업) 반영

### 2.4 데이터 모델
```ts
type Merchant = {
  id: string;            // 게시글 번호 기반 안정 ID
  name: string;          // 상호명
  category?: string;     // 업종 (일반음식점, 편의점 ...)
  roadAddress?: string;  // 도로명주소
  jibunAddress?: string; // 지번주소
  tel?: string;
  lat?: number;
  lng?: number;
  geocodeStatus: 'ok' | 'approx' | 'failed';
  sourceUrl: string;     // 원문 게시글 링크
  updatedAt: string;     // ISO8601
};
```

### 2.5 보조 데이터 소스 (권장 병행)
게시판 스크랩만으로는 좌표가 없고 표기가 불규칙할 수 있다.
아래 공개 데이터에는 **상호명·업종·주소(+일부 위경도)**가 정제된 형태로 들어 있어
스크랩 결과와 병합하면 정확도와 지오코딩 비용이 크게 개선된다.

- 경기데이터드림 「지역화폐 가맹점 현황」 (시군=김포, CSV/JSON/OpenAPI)
- 공공데이터포털 「경기도_지역화폐 가맹점 현황」, 「전국지역화폐가맹점표준데이터」

병합 규칙: `상호명 + 주소 정규화 키`로 매칭 → 좌표는 공개데이터 우선,
없으면 지오코딩 결과 사용, 최신성은 게시판 기준.

## 3. 지오코딩 (주소 → 좌표)

- 1순위: **Kakao Local API** `/v2/local/search/address` (한국 도로명·지번 모두 강함, 무료 쿼터 넉넉)
- 2순위: VWorld 지오코더 (국토부, 무료)
- 실패 시: 주소에서 `동/리` 단위까지 잘라 재시도 → `geocodeStatus: 'approx'`로 표시
- 결과는 `data/cache/geocode.json`에 **주소 정규화 문자열을 키로** 저장·커밋
- 초기 1회 전량 지오코딩(약 1만 건)은 배치로 수 분 소요, 이후는 신규분만

## 4. 웹앱 (web)

### 4.1 기술 스택
- Vite + React + TypeScript
- 지도: **Kakao Maps JS SDK** (한국 지도 품질·클러스터러·길찾기 연동 우수)
  - 대안: Leaflet + VWorld 타일 (키 발급/도메인 등록 없이 시작 가능)
- 상태: 별도 라이브러리 없이 React state + URL 쿼리스트링 동기화
- 배포: GitHub Pages (정적)

### 4.2 화면
```
┌──────────────────────────────────────────┐
│  🔎 [ 상호명·주소 통합 검색 ]  [업종 필터 ▾] │
├───────────────┬──────────────────────────┤
│ 결과 리스트    │                          │
│ · 상호명       │        지 도              │
│   업종/주소    │   (마커 + 클러스터링)      │
│   거리 1.2km   │                          │
│ · ...         │   [이 지역에서 재검색]     │
└───────────────┴──────────────────────────┘
모바일: 지도 전체화면 + 하단 바텀시트 리스트
```

### 4.3 검색 사양
- **통합 검색 한 칸**에서 상호명과 주소를 동시에 매칭 (기본)
  - 부분 문자열 매칭 + 공백 무시 + 초성 검색(`ㄱㅍㅍㅇ` → 김포페이)
  - 상호명 완전일치 > 상호명 접두사 > 상호명 부분 > 주소 부분 순으로 랭킹
- 필요 시 `상호명만 / 주소만` 토글 제공
- 업종 필터 칩, 내 위치 기준 거리순 정렬
- 지도 이동 시 현재 화면 영역(bbox) 내 결과만 리스트에 표시
- 검색어·필터·지도 좌표를 URL에 반영해 링크 공유 가능

### 4.4 성능
- `merchants.json`을 gzip/brotli로 제공 (1만 건 ≈ 1~2MB → 압축 시 수백 KB)
- 마커는 클러스터링 + 화면 영역 밖 제외
- 검색 인덱스는 최초 로드 시 1회 구축 후 메모리 유지, 입력은 150ms 디바운스

## 5. 자동 갱신 & 배포

`.github/workflows/refresh.yml`
- 주 1회(예: 매주 월 03:00 KST) + 수동 실행(workflow_dispatch)
- 증분 스크랩 → 신규분 지오코딩 → `merchants.json` 갱신
- 변경이 있을 때만 커밋 & Pages 재배포
- 지오코딩 키는 GitHub Secrets(`KAKAO_REST_KEY`)로 주입

`.github/workflows/deploy.yml`
- main 푸시 시 `web` 빌드 → GitHub Pages 배포

## 7. 리스크 및 대응

| 리스크 | 대응 |
|---|---|
| **현재 개발 환경에서 gimpo.go.kr 및 지오코딩 API 접근이 차단됨** | 스크랩·지오코딩은 GitHub Actions 러너 또는 사용자 로컬에서 실행. 개발 중에는 고정 샘플 데이터(fixture)로 UI 작업 |
| 게시글 수천~1만 건 → 최초 수집 시간 | `pageUnit` 확대, 동시성 2, 1회성 배치로 처리 후 증분 전환 |
| 사이트 HTML 구조 변경 | 파서를 셀렉터 상수로 분리, 파싱 실패 건수 임계 초과 시 CI 실패로 알림 |
| 지오코딩 실패 주소 | 동 단위 근사 좌표 + "위치 부정확" 배지 표시 |
| 폐업/삭제 가맹점 잔존 | 월 1회 풀 스캔으로 소멸 항목 제거, `updatedAt` 노출 |
| 이용약관·크롤링 예절 | robots.txt 준수, 요청 지연, User-Agent 명시, 공개 데이터 병행 |

## 8. 확정이 필요한 항목

1. 지도 제공자: Kakao(키 발급 필요) vs Leaflet+VWorld(키 없이 시작)
2. 데이터 출처: 게시판 스크랩 단독 vs 공개데이터 병합
3. 배포: GitHub Pages 정적 vs Next.js 서버 배포
